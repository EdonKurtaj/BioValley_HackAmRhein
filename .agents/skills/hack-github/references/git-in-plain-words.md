# Git and GitHub in plain words

| Term | Plain meaning | One-line picture |
|---|---|---|
| Repository (repo) | The project folder plus its full history | A binder that remembers every page it ever had |
| Clone | Download a repo to your computer, history included | Getting your own copy of the binder |
| Commit | A save point with a short note | A dated, signed entry |
| Branch | A separate lane of work | A draft copy you can edit freely |
| main | The shared, official lane | The approved version |
| Push | Upload your commits to GitHub | Filing your entries in the shared binder |
| Pull | Download the team's newest commits | Getting the latest pages |
| Pull request (PR) | A request to bring your branch into main, with a place for comments | Submitting a change for sign-off |
| Merge | Combining a branch into another | Accepting the change into the official version |
| Conflict | Two changes to the same lines; git asks a human to pick | Two people edited the same sentence |
| Revert | A new commit that undoes an old one | A correction entry, the original stays visible |
| .gitignore | A list of files git must never track | The "do not file" list |
| Remote / origin | The GitHub copy of the repo | The shared binder in the office |
| Worktree | A second working folder for the same repo, on another branch | A second desk with the same binder |
| Fork | Your own copy of someone else's repo on GitHub | Photocopying another team's binder to work on |
| Issue | A to-do or bug report on GitHub | A ticket |
| GitHub Actions | Automatic jobs that run on GitHub when you push | A robot that checks every new entry |
