# Analogy bank per track

Starting points, not scripts. Always prefer the person's own words from `domain`. Mention where an analogy breaks when it matters.

| Concept | Life Science | High-tech manufacturing | Architecture / built environment | Social impact / public sector |
|---|---|---|---|---|
| Repository | The controlled document system for this project | The machine's full documentation folder | The project archive with every plan version | The shared case folder |
| Commit | A signed entry in the batch record | A logged change in the change log | A plan revision with index letter and date | A dated note in the case file |
| Branch | A trial run that doesn't touch the validated process | A test setup next to the production line | A design variant you develop in parallel | A draft proposal before it goes to the committee |
| Merge / pull request | Change control: review and approval before it's part of the process | An engineering change request that gets signed off | Coordinating a variant back into the main plan set | Proposal accepted and filed into the official file |
| Merge conflict | Two people edited the same SOP paragraph differently | Two change requests on the same part | Two planners changed the same wall | Two caseworkers updated the same field |
| Worktree | A second bench with a copy of the setup | A second test rig | A second drawing table with a copy of the plans | A second desk with a copy of the file |
| Database | Sample register or LIMS | Historian / MES data | Room book or BIM model data | Client register |
| API | A standard request form between departments | The PLC interface signals other systems read | The IFC exchange format between disciplines | A form another office accepts |
| Frontend / backend | The label and patient leaflet / the manufacturing process behind it | The HMI screen / the controller logic | The facade / the structure and services | The front desk / the back office |
| Bug | A deviation | A fault or alarm | A clash | A process error in the case flow |
| Test | An acceptance criterion checked during qualification | An end-of-line check | A code-compliance check | A check that a rule was applied correctly |
| Deploy | Release after QA approval | Rolling the new program onto the line | Handing the plans to the builder | Going live with a new service |
| Environment variables / secrets | The access badge, never copied into the SOP | Machine passwords, not printed on the panel | Keys to the site, not drawn into the plan | Login data, not written into the file |
| Model / reasoning effort | Choosing between a quick check and a full investigation | Quick visual check vs full diagnosis | Sketch vs detailed plan | Quick triage vs full assessment |
